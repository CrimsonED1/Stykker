How it works

  • Each program gets a folder per version: …\Starter\<name>\<version>\. A copy goes into a new folder and is checked (size and hash) before it is used, so a broken copy never replaces a working one.
  • The program runs from the copy. The source on a share or in a build folder stays free and can be rebuilt while it runs.
  • A new version is the file version of the .exe; if that did not change, a changed file in the folder (size, time, then hash).
  • Stopping: every process whose program file lies in that version's folder is stopped – the program itself and whatever it started from there (StykkerUI and its server). First a polite close (window close, then Ctrl+C for console programs), after 10 s the end. Never by name: the folder is the Starter's own copy, so nothing else runs from it.
  • Before deleting an old version the same check runs: as long as something runs from its folder, it stays.
  • If the source is not reachable (share offline), the program still starts from the last copy.

Decided

  • Interface: Photino, like the windows of HUD, SYS and LLM: the page is local HTML inside the program (no server, no port), drawn without the graphics card. The design system as in the other tools.
  • Stopping: by folder, see above.
  • Name: Stykker Starter.
  • Copies: in %LOCALAPPDATA%\Stykker\Starter, not in %APPDATA%: Roaming is synced with the profile and is no place for 150 MB of binaries.
